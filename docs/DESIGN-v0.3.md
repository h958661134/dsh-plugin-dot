# Dot v0.3 设计：桌面置顶、子任务监控、对齐 ChatGPT Dots

本文回答三个问题：

1. 小精灵能不能置顶显示在桌面上？
2. 怎么监控每个子任务？
3. 对照 ChatGPT Dots，还差什么、怎么补？

资料来源：OpenAI 官方的 [Introducing dots](https://openai.com/index/introducing-dots/)、帮助中心的 [Getting started with your dot](https://help.openai.com/en/articles/20001530-getting-started-with-your-dot)，以及 DSH 0.2.2-rc.1 源码。

---

## 1. 桌面置顶小精灵

### 结论

能做，但**不能放在插件里做**。DSH 插件运行在 Host 进程（Node）里，没有创建系统窗口的 API。只能另做一个独立的小程序。

### 方案比较

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. Electron 壳（推荐）** | 一个透明、无边框、`alwaysOnTop` 的小窗，**直接加载 Host 提供的宠物页面** `/dsh-plugin-dot/pet` | 界面和应用内浮标是同一份代码；能做托盘图标、开机自启、点击穿透、系统通知；Windows 和 Mac 都能用 | 要单独安装一个约 80 MB 的程序 |
| B. PowerShell + WPF 原生窗口 | 插件自带一个 `.ps1` 脚本，用 WPF 画小精灵、用 `Invoke-RestMethod` 轮询状态 | 不用装任何东西，用 `/pet` 一条指令就能启动 | 只支持 Windows；界面要重写一遍，做不出面板里那些交互 |
| C. Tauri | 同 A，但用系统自带的 WebView | 安装包只有 5 MB 左右 | 需要 Rust 工具链，开发和打包门槛高 |
| ~~借用 DSH 自带的 Electron~~ | — | — | 打包后的 Electron 会忽略外部 app 路径，不可行 |

### 推荐架构（方案 A）

```
DSH Host（dsh-plugin-dot/host）                     Dot Pet（独立小程序，Electron）
 ├─ 启动时写 $DSH_HOME/dot/pet.json  ──读取──▶  知道 DSH 的地址 + 本地 token
 │    { origin, token, pid }                     （DSH 每次启动端口可能不同）
 ├─ GET /dsh-plugin-dot/pet  ◀──────加载─────  透明置顶窗口
 │    （宠物 + 面板，复用 client.js）              ├─ 托盘：显示/隐藏、免打扰、开机自启
 ├─ /api/dsh-plugin-dot/*  ◀──带 token──────   ├─ 空闲时点击穿透，不挡鼠标
 └─ 退出时删除 pet.json                           ├─ 状态变成「完成 / 等你 / 到期」时弹系统通知
                                                  └─ DSH 没在运行时：小精灵睡觉，显示「DSH 未运行」
```

- **鉴权升级**：Host 每次启动生成一个随机 token，写进 `pet.json`（只有当前用户可读）。接口同时接受两种调用：DSH 页面内的同源请求，或者带 `X-Dot-Token` 头的请求。
- **双击小精灵**：把 DSH 窗口切到前台。用的是系统的协议唤起或窗口激活，不用改 DSH。
- **代码位置**：放在同一个仓库的 `pet/` 子目录，单独打包发布，不打进插件的 npm 包。

## 2. 子任务监控

### 现状

Dot 把大活派给子代理（`subagent` 工具）后，我们只能看到 Dot 自己是不是在运行，**看不到子代理在做什么、进行到哪一步、有没有卡住**。

### DSH 已经提供的能力

- 每个子代理都是一个**独立会话**，有树状名字（例如 `t3-research`、`t3-research/checker`），可以通过 `ctx.subagents.namesOf()` 和 `listDescendants()` 查到。
- 子代理也会发 `agent/status` 事件，它的工具调用也走 `tools/pre-execute` 和 `tools/result`。全局监听这几个事件就能看到。
- 子代理结束时，父会话（Dot）会自动收到一条完成通知。
- 可以给子代理发消息（`sendMessage`），也可以中断它。

### 设计

**① 子任务和事务一一对应：靠命名约定**

工作手册里规定：派子代理时，`name` 用「事务 id 加简短英文描述」，例如 `t3-pricing`。子代理名字只允许小写字母、数字和连字符，并且要以字母开头，`t3-…` 正好符合。这样 Host 拿到名字就知道它属于哪件事务，不需要猜。

**② Host 全局跟踪子代理**

`dsh-plugin-dot/host` 用 `{ global: true }` 监听 `agent/status`、`tools/pre-execute`、`tools/result`。通过 `ctx.subagents.rootOf()` 判断某个子代理是不是挂在 Dot 会话下，是的话就记录：

| 字段 | 来源 |
|---|---|
| 名字和所属事务 | `namesOf()`，从 `t3-` 前缀解析出事务 |
| 状态：排队 / 运行中 / 等你 / 完成 / 失败 / 已停止 | `agent/status` 加上完成结果 |
| 当前在做什么 | 最近一次工具调用，翻译成中文（「搜索网页」「编辑文件」） |
| 已经走了几步、用了多久 | 每次工具结束计数；首次运行的时间 |
| 最后活动时间 | 超过 5 分钟没有动静，标记为「可能卡住」 |
| 结果摘要 | 完成通知里的输出，截取前 200 字 |

**③ 怎么看到**

- **浮标面板**：已委派的事务下面挂一棵子任务树：

  ```
  ▾ [高] t3 竞品定价调研            运行中 · 6 分钟
      ├─ t3-pricing        ● 正在阅读网页…   第 12 步
      └─ t3-pricing/check  ✓ 完成            第 5 步
  ```

  每一行有两个按钮：「停止」（中断这个子代理）和「补一句」（给它发一条消息，例如「只看国内市场」）。
- **气泡**：子任务完成时提示「t3 的调研完成了，Dot 正在汇总」；卡住时提示「t3-pricing 5 分钟没动静」。
- **`/tasks`**：已委派的事务下面也列出子任务的状态。

**④ 收尾**

子代理完成后，Dot 会自动收到通知，按手册更新事务并汇报结论。Host 这边只负责显示状态，**不替模型改事务状态**，避免两边同时修改冲突。

## 3. 对齐 ChatGPT Dots

这里假设「除了链接」指的是 Dots 连接 4000 多款外部应用的插件生态，所以下表不包括这部分。

| Dots 的能力 | 我们 v0.2 的状态 | 怎么补 | 优先级 |
|---|---|---|---|
| **活动视图**：In progress / Scheduled / Completed，后台工作也能看到 | 只有事务列表 | 面板改成三个标签页：进行中（事务和子任务树）、已排程（读 `ctx.schedule.list()` 里属于 Dot 的提醒和周期任务，可以暂停或删除）、已完成 | P0 |
| **主动汇报、提问、请你决策** | 只有到点提醒 | 加一个「待你决定」队列：等你批准的操作、Dot 的提问、子任务需要的输入，都集中到面板顶部，并显示在气泡上 | P0 |
| **暂停 / 恢复** | 没有 | `/pause`：闸门拒绝所有有副作用的工具，暂停 Dot 的定时任务，小精灵进入睡觉状态；`/resume` 恢复 | P0 |
| **自定义规则的四种行为**：直接做 / 明确要求过才做 / 先问 / 交给你 | 只有 allow、ask、block，而且只按工具名匹配 | 新增 `preapproved`（本轮用户原话里明确要求过才放行，否则转成「先问」）和 `handoff`（拒绝执行，让 Dot 准备好草稿交给你）；规则可以用自然语言描述动作，例如「发邮件」「付款」，由下面的自动审查来判断是否命中 | P1 |
| **自动审查**：按你的指令、规则和安全要求审查有影响的操作 | 只按工具名匹配 | 只对有副作用的工具（命令、写文件、网络写操作、委派）做一次轻量审查：用一个便宜的模型，输入「用户规则 + 本轮指令 + 待执行的调用」，输出允许 / 先问 / 交给你。比 DSH 自带的 auto-review 多了用户自定义规则这一层 | P1 |
| **内置不可绕过的规则**：例如改密码必须你亲自做 | 没有 | 内置一组模型删不掉的规则：付款、改密码或账户安全设置、对外发消息一律「交给你」或「先问」 | P1 |
| **主动研究**：后台只读巡检，形成记忆，提出能帮你做的事 | 没有 | 新增一个只读的 `dot-patrol` 预设：只有读文件、搜索、读事务、记记忆和 `dot_suggest` 这几个工具，从组合层面保证只读。按周期在新会话里运行，巡检逾期事务、待办里的线索、今天的新闻等，产出「建议」进入收件箱。小精灵提示「我有 2 个建议」，点一下就能采纳或忽略 | P1 |
| **周期检查** | 用户得自己用自然语言说 | `/every 每天9点 看看我关注的 GitHub 仓库`：建一个按天重复的定时任务，出现在「已排程」里 | P1 |
| **从反馈中学习** | 只有通用记忆 | 记忆增加 `feedback` 类别：用户纠正 Dot 时（「不对」「以后别……」），记成一条工作方式偏好，每次优先注入上下文；面板里加「Dot 记得什么」页面，可以查看、编辑、删除 | P1 |
| **名字、头像、宠物形象** | 名字固定叫 Dot，形象固定 | `/dot name 小管家` 改名，并同步到人设；提供 4 到 6 套小精灵外观（颜色和表情），在面板里选 | P2 |
| **每个任务一个独立对话，主对话保持干净** | 所有事情都在同一个会话里 | 派活本来就是独立的子代理会话；面板里的子任务行可以「打开会话」，前提是 DSH 前端支持按会话 id 跳转，需要再查 | P2 |
| **重置** | 没有 | `/reset`：确认后备份并清空 `state.json`，删除 Dot 的定时任务 | P2 |
| **多渠道**：Slack、Teams、短信、语音 | 只有 DSH 窗口 | 不在这一版做。你已经装了 ds-harness-remote，手机上本来就能用 | P3 |
| **云电脑、接管、可选连接本地电脑** | Dot 本来就跑在你的电脑上 | 不需要。可以考虑把 DSH 的 `browser-use` 加进 Dot 预设，让它能操作浏览器 | P3 |
| **任务的不同环节用不同模型** | 没有 | 子代理支持选模型：巡检和审查用便宜模型，深度工作用强模型，在配置里设 | P3 |
| **多个 dot 组队、专家型 dot** | 没有 | 以后再做：「专家预设」，例如「调研员」「写手」，作为子代理的预设 | P3 |

Dots 在评测里被吐槽最多的两点是「不够主动」和「慢」。对我们来说，**主动研究**和**快捷指令**正好是差异化的地方：巡检用便宜模型、只读、成本可控；快捷指令完全不经过模型，秒回。

## 建议的实施顺序

| 批次 | 内容 | 依赖 |
|---|---|---|
| **v0.3a** | 子任务监控（命名约定、Host 全局跟踪、子任务树、停止和补一句）+ 活动视图三个标签 + 待你决定队列 + `/pause` | 只用 DSH 已有的 API |
| **v0.3b** | 桌面置顶小精灵（Electron 壳、pet.json、token、托盘、系统通知） | 依赖 v0.3a 的宠物页面 |
| **v0.4** | 规则的四种行为 + 自动审查 + 内置硬规则 + 主动研究预设 + `/every` + 反馈记忆 | 自动审查要在 Host 里调用模型，需要先确认 `ctx.llm` 的用法 |
| v0.5 | 名字和外观、重置、多模型分工、专家预设 | — |

## 风险

- **监听全局事件的开销**：`{ global: true }` 会收到所有会话的事件，包括你平时的编码会话。处理逻辑必须很轻：先用 `rootOf` 判断不是 Dot 的子树就立刻返回，不做任何记录。
- **命名约定依赖模型遵守**：模型没按 `t3-` 命名时，子任务仍然显示在「未关联」分组里，不会丢。
- **桌面小精灵要求 DSH 在运行**：DSH 关掉时只能显示「睡觉」状态。这和 Dots 云端全天候运行有本质区别，这是本地优先的取舍。
- **自动审查多花 token、增加延迟**：只审查有副作用的调用，并且允许在配置里关掉。
