# 桌面精灵

Dot 的小精灵可以跳出 DSH 窗口，常驻在桌面上：始终置顶，拖到屏幕边缘会吸附并半隐藏。它仍然是插件的一部分，不需要单独安装，DSH 退出时它也跟着退出。

## 为什么不能在 DSH 里直接开窗口

- DSH 桌面版是 Electron 应用，但插件跑在 `ELECTRON_RUN_AS_NODE=1` 的纯 Node 进程里（`runtime/bin/node.cmd`），拿不到 `BrowserWindow`。
- 网页端注入的脚本也开不了窗口：`setWindowOpenHandler` 一律返回 deny。
- DSH 注册了 `dsh://` 协议，`dsh://open` 会把主窗口拉到前台。

所以由 Dot 的 Host 启动一个系统自带的 PowerShell 5.1 + WPF 窗口，并对它的整个生命周期负责。

## 架构

```
DSH 运行时（Node）
 └─ Dot Host
     ├─ GET  /status?desk=1   精灵要显示的一切：表情、气泡、角标，以及 Host 算好的卡片（petcards.js）
     ├─ POST /task /notice /say   卡片按钮和输入框，和网页小精灵用的是同一组接口
     ├─ POST /focus           精灵要打开某个会话 / Dot 窗口 / 会话总览时，把目标交给这里
     ├─ GET  /focus/wait      网页端挂着的长轮询（最长 25 秒），有新目标立刻返回
     └─ 看管 → 桌面精灵（desktop.js 启动 pet-win.ps1）
                  └─ 点「打开」：先把 DSH 主窗口直接切到前台（失败才用 dsh://open），再 POST /focus
                                     ↓
              DSH 网页端（client.js）的长轮询立刻拿到 focus，跳过去，再回执清掉
```

| 文件 | 职责 |
|---|---|
| `lib/desktop/pet-win.ps1` | 精灵窗口：画精灵、气泡、面板，执行卡片上的动作。只会调 `/task` `/notice` `/say` `/focus` 这四个接口，卡片里给的其他路径一律不执行 |
| `lib/desktop.js` | 看管者：决定要不要启动（`wantsDesktopPet`），负责启动、停止和异常重启 |
| `lib/petcards.js` | 卡片规则：和网页小精灵一致，在 Host 端算好，精灵只负责画 |
| `lib/host.js` | `/focus` 接口；`/status` 返回 `desktopPet`、`focus` 和 `desk` |
| `lib/client.js` | 桌面精灵在跑时，网页里的小精灵让位；读到 `focus` 就跳转并回执 |

## 什么时候启动

| 配置（`dsh-plugin-dot` 行） | 结果 |
|---|---|
| 不写 `pet` | DSH 桌面版（Windows）用桌面精灵。命令行起的网页版，以及 macOS、Linux，用网页小精灵 |
| `pet: 'desktop'` | 用桌面精灵（目前只支持 Windows） |
| `pet: true` | 只用网页小精灵 |
| `pet: false` | 两个都不要 |

判断是不是桌面版，看运行时的入口脚本：桌面版是 `dsh-desktop-host/lib/index.js`，命令行（`dsh.cmd`，包括网页版）是同一个包里的 `cli.js`。最初用的是环境变量 `DSH_DESKTOP_NODE_EXECUTABLE`，在正式环境里发现桌面版运行时并不带这个变量，就改成了看入口脚本。

## 能做什么

> v1.2 起精灵住到了任务栏上，身体语言、专注、问候、工作时长和按键统计见 [DESK-BUDDY.md](DESK-BUDDY.md)。下面是面板和窗口本身的行为。

- **表情**：空闲、在忙（眼睛左右看）、等你确认、刚做完、有事提醒、暂停。每 3～6 秒眨一次眼。
- **手里的东西**（原来的角标）：有卡片时举着一个包裹，上面写张数；急事（等你确认、出错、逾期）是红色，其他是橙色；只有跑完的会话时是信封。
- **气泡**：Dot 有话说时出现在精灵旁边，点一下打开面板。
- **单击**：打开或收起面板。面板里有「需要你」的卡片（最多 3 张）、快捷按钮、输入框、暂停 / 恢复，以及「打开 Dot」「会话总览」。
- **Alt+Shift+D**：在任何地方都能打开面板，并把光标放进输入框。如果这个组合键已经被别的程序占用，就不注册，其余功能照常。
- **拖动**：拖到离屏幕左右边缘 28 以内会吸附。吸附后鼠标离开 2.5 秒就滑进去，只露出 22；鼠标移上去或有新气泡时会滑出来。
- **双击**：直接打开 Dot 会话。
- **和 Dot 对话**：在面板输入框里说话，Dot 的回复会显示在面板里，点「在 DSH 里看」可以跳过去。等回复最多 3 分钟。输入框按 ↑/↓ 翻历史，Esc 收起面板。
- **拖放**：把文字或文件拖到精灵身上，输入框会填成一条 `/task …`，确认后回车。
- **打开 DSH**：精灵进程是被点击的前台窗口，有权直接把 DSH 主窗口切到前台（`SetForegroundWindow`），不行时再走 Alt 键的办法。DSH 缩在托盘、没有窗口时，用 `dsh://open` 唤起。跳转目标通过长轮询送到网页端，不用等后台轮询。
- **不会卡**：精灵的网络请求全部异步，结果由 40ms 的消息泵按名字交给处理函数。
- **右键**：打开 Dot、会话总览、今日简报、今日统计、专注、换装、回到任务栏上、暂停 / 恢复、安静模式、关掉桌面精灵。用这里关掉的，在 DSH 下次启动之前不会再拉起。
- 位置和吸附的边记在 `$dataDir/desktop-pet.json`。排查问题用的日志在 `desktop-pet.log`，最多 64KB。

## 安全

- 精灵只连 Dot 自己的本机接口。写操作和网页小精灵走同一套校验：只接受本机 Host、拒绝跨域、必须带 `X-Dot-Client` 头和 JSON。
- 写接口只有四个白名单路径，测试里会逐个核对。
- `/focus` 只登记「要打开哪里」，真正的跳转由 DSH 网页端完成。目标长度有上限，一分钟后作废。
- 启动时用 `-ExecutionPolicy Bypass`，只对这一个进程生效，只运行插件目录里的这一个脚本，不改系统的执行策略。

## 实测（隔离 DSH，Windows 11，高 DPI）

| 项 | 结果 |
|---|---|
| Host 自动拉起 | 配置了 `pet: desktop` 后重启，精灵出现，`/status` 返回 `desktopPet: true` |
| 显示 | 红色提醒表情，角标是卡片张数 2，气泡显示「「交周报」已逾期」，背景透明，浮在其他应用上面 |
| 面板 | 按 Alt+Shift+D 后面板弹出：一张绿色的「跑完了」卡、一张红色的「已逾期」卡、快捷按钮、输入框和两个入口按钮。光标已在输入框里 |
| 打开 DSH 里的某处 | 登记 `nav: sessions` 后，网页端跳到会话总览并回执；登记 `nav: dot` 后跳到 Dot 会话 |
| 网页小精灵让位 | 桌面精灵在跑时，DSH 页面里的小精灵不显示 |
| 跟着 DSH 退出 | 结束 DSH 后 5 秒内精灵也退出了 |
| 异常重启 | 强制结束精灵进程后，3 秒内被重新拉起 |
| 第一次的坑 | 用 `SizeToContent` 时，窗口变宽后只画出左边一部分（透明窗口改尺寸时 WPF 的已知问题）。改成固定大小的窗口后正常 |
| 第二次的坑 | 事件处理里用 `GetNewClosure()` 后，闭包看不到脚本里定义的函数。改成把数据放进控件的 `Tag` |

## 功耗

v1.2 的桌宠在隔离 DSH 上实测，每种状态 60 秒，用进程的 `TotalProcessorTime` 计算。机器是 AMD Ryzen 7 5800H（16 线程），Windows 11，2 倍缩放。

| 状态 | 单核占用 | 占整机 | 内存（工作集） |
|---|---|---|---|
| v1.1 的精灵（对照） | 0.99% | 0.06% | 203 MB |
| 醒着，含随机溜达 | 1.87% | 0.12% | 225 MB |
| 陪你休息 / 打盹 | 1.61% | 0.10% | 224 MB |
| 陪你专注 | 1.38% | 0.09% | 225 MB |
| 数按键，跟着打字（每秒 5 下） | 1.09% | 0.07% | 223 MB |
| 贴边藏起来 | 0.96% | 0.06% | 224 MB |

- **开销在哪**：`AllowsTransparency` 的透明窗口是软件渲染的，身上任何一处动了，整个窗口都要重画。实测贴边藏起来时帧率已经降到 4 帧，只要还在做呼吸动画，CPU 就和平时差不多；停掉呼吸动画后马上降到 v1.1 的水平。
- **所以帧率是分档的**：走路、掉落、粒子、吃东西、打字时 30 帧；平时 10 帧；打盹 8 帧；贴边藏起来时 4 帧，并且不做呼吸动画。
- 第一版一直 30 帧，单核占用约 2.5%。
- 内存主要是 PowerShell 和 WPF 本身。
- 每分钟上报一次工作时长，Host 写一次 `state.json`，开销可以忽略。

**复现**：用隔离的 `DSH_HOME` 起一个网页版 DSH（`pet: desktop`），再对精灵进程测 60 秒：

```powershell
$p = Get-Process -Id <精灵 pid>; $a = $p.TotalProcessorTime.TotalMilliseconds
Start-Sleep 60; $p.Refresh(); ($p.TotalProcessorTime.TotalMilliseconds - $a) / 600   # 单核百分比
```

精灵的 pid 在 `desktop-pet.log` 里（`start pid=…`）。

## 录动图（开发用）

设置环境变量 `DOT_PET_FRAMES` 为一个已存在的目录，再启动 DSH，精灵就会每 100ms 把自己画成一张透明 PNG，文件名是 `序号_窗口左_窗口上.png`。录帧用的是 `RenderTargetBitmap`，只画精灵自己的窗口，不截屏，所以不会录到桌面上的其他内容。README 里的动图，就是把这些帧按窗口位置合到一张浅色背景上得到的。不设这个变量时，这段代码不运行。

### 正式环境（DSH 桌面版）

| 项 | 结果 |
|---|---|
| 默认开启 | 不写 `pet` 时，桌面版自动拉起精灵，全局热键注册成功 |
| 跳转延迟 | DSH 在后台时登记 `nav: sessions`，网页端 146 ms 后回执（以前靠 10 秒一次的后台轮询） |
| 拉到前台 | 调用精灵里的 `BringToFront`，前台窗口随即变成 DSH 主进程的窗口 |
| 第三次的坑 | 脚本被写成了两个 BOM，PowerShell 报错，看管者连续 3 次重启后放弃。测试里加了「只能有一个 BOM」的检查 |

还没在真人操作下验证的：鼠标拖动和吸附手感、卡片按钮的点击、多显示器、DSH 桌面版（不是隔离网页版）里的默认开启。
