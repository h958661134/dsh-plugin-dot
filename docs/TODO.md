# 待办闭环与会话命名

## 待办：从记下到勾掉，每一步都有出口

DSH 自带的 todo 只管当前这一轮编码。Dot 的待办跨会话保留，由小精灵随时递到你手边。目标是「简单又好用」：记一件只要一句话，勾一件只要一下，每个操作都能撤销。

| 环节 | 怎么做 | 不调模型 |
|---|---|---|
| **收** | 一句话记下：`明天9点 交周报`、`每周一9点 周会`、`今天 买牛奶 !高`、`准备周会；整理数据；写结论`（用「；」分出小步骤）。桌面精灵面板、Dot 窗口、`/task`、拖文字或文件到精灵身上都行 | ✓ |
| **理** | 自动分成五组：逾期、今天、之后、收件箱（没定时间）、等别人。☀ 把收件箱里的事放进今天，过了当天自动回到收件箱 | ✓ |
| **做** | 拆小步骤逐个勾；「交给 Dot」把这件事连同没做完的步骤交给 Dot，能做的它做，要你拍板的先问你 | 交给 Dot 时才调 |
| **跟** | 「在等别人…」写上等谁，两天后上午 10 点提醒你追；推迟有五个预设：1 小时后、今晚 8 点、明早 9 点、周末、下周一 | ✓ |
| **结** | 勾掉有划线动画，回执旁边有「撤销」；周期待办勾掉后自动排下一次，撤销时下一次一起撤；关联的会话跑完时，通知卡上直接给「勾掉待办」 | ✓ |

### 时间和提醒：先记下，提醒是可选的

待办往往没有时间，所以**任何一句话都能记下，不会因为时间的问题被拦住**。只有写了时间，才会到点提醒。

| 你写的 | 结果 |
|---|---|
| `精细化插件使用`（没写时间） | 记下，不提醒。从精灵、「今天」页或 `/remind` 记的放进今天，从待办页或 `/task` 记的进收件箱 |
| `今天 精细化插件使用`（只说了今天） | 放进今天，不定钟点，也不提醒 |
| `明天 交周报`、`周五 交周报`（只说了以后某天） | 截止那天，那天早上 9 点提醒 |
| `下午3点 开会`、`1小时后 喝水` | 到点提醒 |
| `今天9点 X`，但现在已经 10 点了 | 按晚上 21:00 提醒，并且告诉你是这么理解的 |
| `今天上午9点 X`，但现在已经 10 点了 | 放进今天、不提醒，并说明「09:00 已经过了」 |
| `等会`、`下班前`、`睡前`、`周末`、`下周`、`月底` | 半小时后、18:00、22:00、周六 10:00、下周一 9:00、月底那天 18:00 |

在待办上点 ⏰ 就能补一个提醒，或者改时间：半小时后、1 小时后、下班前、今晚 8 点、明早 9 点、周末、下周一，也可以直接写「周五18点」。`/remind` 记的也是一件待办，到点提醒，在清单里能勾掉。

### 数据

`Task` 多了几个可选字段，旧数据不用迁移：

| 字段 | 含义 |
|---|---|
| `today` | 放进「今天」的日期（`YYYY-MM-DD`），只在那一天算数 |
| `steps` | 小步骤 `[{ text, done }]`，最多 20 个 |
| `repeat` | `{ label, timing }`，`timing` 和 DSH 定时服务的格式一样（`daily` / `weekly` / `every`） |
| `waitingOn` | 等谁、等什么（`status` 为 `waiting` 时） |

纯计算都在 `lib/todo.js`，包括分组、下一次的时间、推迟预设和标题好坏的判断，方便测试。

### 接口（`POST /api/dsh-plugin-dot/task`）

| action | 参数 | 说明 |
|---|---|---|
| `add` | `text`, `today?` | 一句话记一件，返回 `id` |
| `done` / `drop` | `id` | 返回 `undo`（`undo-close`，周期待办带上下一次的 id） |
| `undo-close` | `id`, `next?` | 重新打开，删掉顺手生成的下一次，提醒建回来 |
| `today` / `untoday` | `id` | 放进 / 移出今天 |
| `step` | `id`, `op`（add / toggle / remove / edit）, `index?`, `text?` | 步骤全勾完时返回 `allDone: true` |
| `wait` / `resume` | `id`, `waitingOn?` | 等别人 / 接着办 |
| `snooze` | `id`, `to`（1h / tonight / tomorrow / weekend / nextweek） | 返回 `undo` |
| `due` | `id`, `due`（ISO 或 null）, `today?` | 撤销推迟用 |
| `delegate` | `id` | 把这件事交给 Dot |
| `edit` / `reopen` / `delete` / `clear-completed` | | 和以前一样 |

## 会话命名：不再有「未命名会话」

**原因**：DSH 的会话标题是第一句话发出后，由模型异步生成的。Dot 第一次看到会话开始跑时，标题往往还没生成，以前就记成了「未命名会话」，之后也不再更新。

**现在的做法：**

1. **临时标题**：正式标题还没有时，用你在那个会话里说的第一句话（最多 24 个字）。连第一句话都读不到时，显示「新会话 · 14:05」。
2. **持续补正**：会话状态变化、调用工具、打开总览时，每个会话最多每 10 秒查一次正式标题，查到就换上。临时标题不会覆盖正式标题。
3. **哪些名字需要整理**：没标题、临时标题、太笼统（「你好」「继续」「测试」或两个字以内）、和别的会话重名、超过 36 个字。总览里会标出来。
4. **改名**：
   - 自己改：总览卡片上点 ✎，直接生效。
   - 让 Dot 起名：总览顶部的「让 Dot 起名」、桌面精灵的「整理会话名」，或者巡检发现名字不清楚的会话攒到 3 个时出的建议卡。Dot 会先读每个会话在做什么，再用 `dot_sessions rename` 一次性提出来，放进建议收件箱。**你点了才改**，改完有一张「撤销」卡，可以改回原名。
   - 改名优先走 DSH 的 `sessionController.rename`，没加载的会话也能改；没有这个接口时，只能改已加载的会话。

巡检本身不调模型。只有你点了「让 Dot 起名」，Dot 才会去读会话、起名字。
