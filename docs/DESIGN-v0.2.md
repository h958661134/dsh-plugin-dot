# Dot v0.2 设计：好上手、看得见

v0.1 的问题：能力都在，但用户**不知道 Dot 能干什么**，也**不知道该怎么说**；每件事都要等模型想一轮，所以显得慢、显得笨。

v0.2 只解决两件事：

1. 让人一眼看到 Dot 在干嘛（想法 1：桌宠）；
2. 让人不用想就能用起来（想法 2：快捷操作 + 意图理解）。

---

## 想法 2：快捷操作与意图理解 —— 接纳，优先做

这是「笨」的根因，收益最大，先做。分三层，从「零思考」到「随便说」。

### 第 1 层 · 发现：打开就知道能干什么

| 入口 | 行为 | 成本 |
|---|---|---|
| **快捷按钮条** | 选中 Dot 预设时，输入框上方出现一排按钮：`今日简报` `记一件事` `设个提醒` `帮我调研` `我的规则`。点按钮会往输入框填入模板（如「记一件事：」），或者直接执行 | 前端插件 |
| **`/dot` 能力卡** | 不经过模型，秒出一张卡片：Dot 能做的 6 类事，每类给一句示例和对应的快捷指令 | 斜杠指令 |
| **首次见面** | 记忆和事务都为空时，Dot 第一句话先自我介绍（三行）+ 提议每天的简报 + 问用户怎么称呼 | 提示词 |

能力卡的内容（也是 Dot 的「能力清单」）：

| 能力 | 随口说 | 快捷指令 |
|---|---|---|
| 记事务 | 「周五前把报价单发给老王」 | `/task 周五 发报价单给老王` |
| 提醒 | 「明早 9 点提醒我开会」 | `/remind 明早9点 开会` |
| 记住我 | 「我不吃辣，周末不看工作消息」 | `/note 不吃辣` |
| 简报 | 「今天有什么事？」 | `/brief` |
| 代办 / 调研 | 「帮我对比三款降噪耳机」 | （对话） |
| 规矩 | 「以后上网前先问我」 | `/rules` |

### 第 2 层 · 快捷指令：不经过模型，秒回

用 `ctx.commands.register` 在 Dot 预设作用域里注册。handler 直接操作存储，不消耗 token，延迟在毫秒级。（DSH 的指令名只能用小写 ASCII，所以没法用中文指令名。）

| 指令 | 作用 | 示例 |
|---|---|---|
| `/dot` | 能力卡 + 当前状态（几件事、几条记忆、几条规则） | `/dot` |
| `/task <时间?> <内容> [!高] [@dot]` | 新建事务；带时间时**同时**自动建一个提醒 | `/task 周五18点 交周报 !高` |
| `/tasks` | 列出进行中的事务 | `/tasks` |
| `/done <id…>` | 标记完成，可以一次多个 | `/done t3 t5` |
| `/remind <时间> <内容>` | 只建提醒，不记事务 | `/remind 30分钟后 喝水` |
| `/note <内容>` | 记一条长期记忆 | `/note 我老婆生日 3 月 8 日` |
| `/brief` | 立刻输出一份结构化简报（不经模型）；加 `/brief ai` 则交给模型写成口语化汇报 | `/brief` |
| `/rules` | 列出规则 | `/rules` |

**中文时间解析器**（`lib/when.js`，纯函数，可测）：支持 `今天/明天/后天/大后天`、`周五/下周三`、`早上/上午/中午/下午/晚上 + N点(半)`、`N分钟/小时/天后`、`11-12`、`11月12日`、`2026-11-12 09:00`。解析不出来时不瞎猜：把整句交给模型（`agent.followup`），并在回复里说明「这句我没看懂时间，交给 Dot 处理了」。

提醒直接调用 `ctx.schedule.create({ title, prompt, timing: { kind: 'at', … }, target: { kind: 'session', … } })`，投递到当前 Dot 会话。提醒 id 写进事务的 notes；事务完成时自动删掉对应提醒。

### 第 3 层 · 意图理解：随口说也能秒懂

快捷指令覆盖的是高频操作；其余情况由模型处理，目标是**一轮工具调用就落地**。

1. **新工具 `dot_capture`**：把「记事务 + 建提醒 + 记记忆」合成一次调用。模型只需要从用户的一句话里抽取结构（`tasks[] / reminders[] / memories[]`），一次落库。原来要 3 次工具调用、3 轮往返，现在 1 次。
2. **先落地，再确认**：工作手册改为「能抽取就立刻执行，用一句话回报结果，例如：已记下 t3，周五 18:00 提醒你。用户说不对再改」，不再先问后做。缺信息时用合理默认值（没给时间 = 不设提醒，没给优先级 = 中）。
3. **意图速查表**：在手册里加上 12 条左右的「用户原话 → 该调用什么」示例，覆盖常见说法。这对 DeepSeek 这类模型很有效，而且内容固定，不破坏 KV Cache。
4. **委派模板**：「帮我调研 / 整理 / 写」这类请求，统一走：建事务（owner=delegated）→ `subagent`（带明确的交付格式）→ 完成后更新事务并汇报。用户只看到开头和结尾两句话。

## 想法 1：桌宠 —— 接纳，分两期

### 先说结论

真正的「桌面宠物」（悬浮在所有窗口之上、DSH 关着也在）**DSH 插件做不了**：插件运行在 Host 进程里，没有创建系统窗口的 API。所以分两期：

| | A 期（v0.2）：应用内浮标 | B 期（v0.3）：独立桌宠 |
|---|---|---|
| 形态 | DSH 窗口右下角的小精灵 + 气泡 | 透明、置顶、可拖动的小窗，独立进程 |
| 可见范围 | DSH 窗口里；web 版和手机远程也能看到 | 整个桌面，DSH 窗口最小化也在 |
| 实现 | 前端插件（和 sidebar-balance 同样的注入方式） | 单独的小 Electron 应用 `dot-pet`，读取 Host 的状态接口 |
| 分发 | 跟着 dsh-plugin-dot 一起装 | 另装一个 exe（单独发布） |
| 工作量 | 小 | 中（窗口、托盘、开机自启、鉴权） |

两期共用同一套**状态接口**和**界面组件**，所以 A 期不会白做。

### 状态从哪来：Host 侧状态中枢

新增一个全局（非预设内）的 Host 插件 `dsh-plugin-dot/host`：

- 监听 `agent/status`（idle / running）、`session/event`（正在调用哪个工具）、Dot 自己的规则闸门（返回 ask 时说明在等用户确认）、`dot` 存储的变化。
- 只统计用 Dot 预设的会话。
- 对外提供：
  - `GET /api/dsh-plugin-dot/status`：返回当前快照；
  - `GET /api/dsh-plugin-dot/events`：SSE 推送，状态一变就推。
- A 期走 DSH 自带的浏览器鉴权；B 期在 `$DSH_HOME/dot/pet-token` 生成本地 token，只监听 127.0.0.1。

状态模型（宠物的表情就由它决定）：

| 状态 | 判定 | 宠物表现 | 气泡示例 |
|---|---|---|---|
| 休息 | 没有 Dot 会话在运行，也没有逾期事务 | 打盹 | （不显示） |
| 忙碌 | 有 Dot 会话处于 running | 埋头干活，带进度点 | 「正在调研降噪耳机… 第 3 步」 |
| 等你 | 规则闸门或提问工具在等用户 | 举手 | 「有 1 件事需要你确认」 |
| 提醒 | 有逾期或 1 小时内到期的事务 | 晃铃铛 | 「周报 18:00 截止，还剩 40 分钟」 |
| 完成 | 委派的事务刚变成 done（显示 30 秒） | 比耶 | 「竞品调研好了，点我看」 |

### 交互（A、B 两期一致）

```
          ╭──────────────────────────╮
          │ 正在调研降噪耳机… 第 3 步 │   ← 气泡：一行字，8 秒后自动收起
          ╰────────────┬─────────────╯
                     (•ᴗ•)                ← 小精灵：状态决定表情和动画
单击 → 展开快捷面板：
  ┌─────────────────────────────┐
  │ 进行中 3 · 逾期 1 · 委派 1   │
  │ ▸ [高] 交周报  今天 18:00    │
  │ ▸ 等供应商报价              │
  │─────────────────────────────│
  │ [今日简报] [记一件事] [提醒] │   ← 与想法 2 的快捷按钮复用
  │ [ 跟 Dot 说点什么…       ⏎ ]│   ← 一句话输入，发到最近的 Dot 会话
  └─────────────────────────────┘
双击 → 跳到正在运行的 Dot 会话
```

- 面板里的输入框调用 Host 的 `POST /api/dsh-plugin-dot/say`，由它对最近的 Dot 会话执行 `followup()`；以 `/` 开头的输入走快捷指令。
- 不打扰原则：气泡只在状态变化时出现，同一件事只提醒一次；可以开免打扰。

## 实施顺序

| 步骤 | 内容 | 验收标准 |
|---|---|---|
| 1 | `lib/when.js` 时间解析 + 测试 | 覆盖上面列出的说法；解析不出时明确返回失败 |
| 2 | 快捷指令 7 个 + `/dot` 能力卡 + `ctx.schedule` 自动建提醒 | 在桌面版输入 `/task 明天9点 交周报`，事务和提醒同时出现，全程不调用模型 |
| 3 | `dot_capture` 工具 + 工作手册改版（先落地、速查表、首次见面） | 一句「周五前把报价单发给老王，提前一天提醒我」只产生 1 次工具调用 |
| 4 | Host 状态中枢 + status / events 接口 | 跑任务时状态从 idle 变成 running 再变回 idle，接口实时推送 |
| 5 | 应用内浮标（A 期）+ 快捷按钮条 | 桌面版右下角出现小精灵，五种状态都能看到 |
| 6 | 独立桌宠（B 期，v0.3） | 另起一个项目做 |

步骤 1–3 不依赖前端，风险最低、见效最快；步骤 4–5 需要逆向 DSH 前端注入方式（有 sidebar-balance 可以参考），工作量主要在这里。

## 风险

- **前端注入是非公开约定**：`tapIndex` 和 `__ModuleLoader__` 来自现有第三方插件的做法，不是文档承诺的 API，DSH 升级后可能失效。对策：浮标做成可选项，加载失败不影响 Dot 主体。
- **`ctx.schedule` 只存在于提供定时服务的 profile 里**：desktop 和 web 有，headless 没有。对策：在 `inject` 里设为可选依赖，没有时 `/remind` 提示用户改用对话。
- **独立桌宠的鉴权**：本地 token 文件加上只监听回环地址；不提供远程访问。
